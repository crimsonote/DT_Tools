# 观战者机制与房主观战（耐久笔记）

> 用途：这两条链**改动前必读**。房主观战（`Patches/System/HostSpectate/`）不是自造能力，
> 它只是"把房主变成游戏原生的观战者"，剩下全靠原版语义与 `Patches/System/SpectatorJoin/`。
> 本文件把两件事写清：**原版观战者机制长什么样**（带行号可复核），**我们踩过的坑与取向**。
>
> 口径：正文里的 `ACS:<行号>` = 反编译转储 `.tmps/decomp/Assembly-CSharp.decompiled.cs`
> （180168 行，2026-09-22）的行号 —— 该文件在 `.tmps` 下、**不进版本库**，是本地核对材料。
> 另一条口径是**方法名**：行号会漂，方法名不会，改代码时优先按方法名定位。
> ⚠️ 该转储与游戏当前程序集（`libs/Assembly-CSharp.dll`，与游戏安装目录那份字节一致）**尚未重新核对**，
> 详见 §8。

## 1. 一句话模型

**房主观战 = 一个"已经在房间里的玩家，在进入选人之前被标成观战者"。**

由此推出全部行为，且**不需要新造任何观战者语义**：

| 关注点 | 由谁提供 |
| --- | --- |
| 不计人数 / 不需准备 / 选人不占位 / 不进存活池 | 上游 `SpectatorJoin` 已有的规则补丁（人数口径、`CheckAllPlayerReady`、`StartPick` 整替、`PickCharacter` 忽略） |
| 开局转幽灵观战（幽灵化 + 引导包 + 幽灵可见性） | **原版** `GameRoom.EnterSpectator`（ACS:170631） |
| 房主客户端"我现在是观战者" | **roster 里自己那条 entry**（原版只在进房包写过一次，之后唯一写入口是上游 `RosterSpectatorPatch`） |
| 大厅/选人阶段别人看不到他 | **按收件人分包 roster**（见 §5.1） |
| 回大厅复位 | **原版** `GameRoom.StartLobby`（ACS:170251-170255） |

## 2. 服务端机制地图（`Server.Game`）

### 2.1 状态机与开局时序（最容易搞错的一段）

- `GameRoom.ChangeGameState(EGameState)`（ACS:169991-170002）**同步**置 `State = state`，
  然后交给私有重载 `ChangeGameState(prev,next)`（ACS:170004-170017）：
  `BroadcastPacketAndWaitResponse(S_CHANGE_GAME_STATE, 回调)`。
- 回调里才跑 `BetweenState()` / `EndState(prev,next)` / `StartState(next)`。
- `EndState`（ACS:170052-170078）里 `case PickCharacter: if (next == Survive) GameStart();`
  ⇒ **`GameRoom.GameStart()` 是在"选人→存活"的客户端应答回调里跑的**。
- `StartState(PickCharacter)` → `StartPick()`（ACS:170035）。
- 选人倒计时：`PickCharacterTick`（ACS:171038-171086）在 `num - stopWatch == -5` 时
  `ChangeGameState(Survive)`（ACS:171081）。

⇒ 两条硬结论：

1. **在 `GameRoom.GameStart()` 的 Prefix 里，`State` 已经是 `Survive`**
   （`State` 在 169996 就写了，`GameStart` 在回调里才跑）。
2. **标记观战者的时点必须早于 `StartPick`**：`StartPick` 的整替体按 `!IsSpectator` 挑真实玩家
   （上游 `Feature.GameStart.cs` 的 `PrefixStartPick`），晚了房主就进存活池、参与角色分配。

### 2.2 进房准入（`HandleEnterPlayer`，ACS:170477-170527）

```text
_banned → ErrorKicked
flag3 && !flag4 → ErrorDuplicateAccount          // flag4 = 同账号残留 && 全假人 && State != Lobby
(!flag4 && RoomMemberCountForMetadata() >= 8) || !ObjectUtils.HasFreeSeat() → ErrorRoomFull   // ACS:170497
IsMigrating || IsTransitioning || NoneState || PickCharacter || TotalResult → ErrorRoomBusy
Trial && !TrialManager.AcceptsSpectator → ErrorRoomBusy
build 不一致 → ErrorBuildMismatch / 重名 → DuplicationError
State != Lobby → flag2 = true（= 以观战身份进）                  // ACS:170523-170526
```

- 中途加入的观战者会**随机分到一个游戏区出生点**（ACS:170560-170568），
  这是原版"观战者也能看到地图"的支点（§3.4）。
- 人数上限的**唯一**闸门就是 `RoomMemberCountForMetadata() >= 8`（或 `[LobbyMaxPlayers]` 的 `MaxMembers`，
  见 `LobbyMaxPlayers/Patch.EnterPlayer.cs:106`、`SpectatorJoin/Feature.Enter.cs:91`）。
- `ObjectUtils` 座位共 **16** 个、按 `playerId-1` 记（ACS:160884-160964），Steam 容器也是 **16**
  （`SteamLobbyManager.CreateLobby(..., 16)`，ACS:160137；`MaxMembers = 8` 那个常量 ACS:160010 **全文件无人引用**；
  `SessionManager.SetInfo` 是空壳，ACS:160985-160987）。
  ⇒ **房主不占名额时，房间能装 8 名真实玩家（共 9 人）**。

### 2.3 roster：客户端"房间里有哪些人"的唯一数据源

| 方法 | 行为 |
| --- | --- |
| `BuildRosterPacket()`（ACS:169764-169788） | 按 `Players` 逐条构造 `RosterEntry`，**带 `IsSpectator`**（ACS:169783）与 `HostPlayerId` |
| `BroadcastRoster()`（ACS:169790-169796） | `if (!IsMigrating) Broadcast(BuildRosterPacket())` —— **一个包发给所有人** |
| `MarkRosterDirty()` / `ConsumeRosterDirty()`（ACS:169752-169762） | 置/取脏位 |
| 泵：`HostManager.Update`（ACS:159718-159738） | `_rosterAcc >= 1f \|\| 脏` → `BroadcastRoster()` ⇒ **每秒至少一次** |
| `Broadcast(IMessage,int)`（ACS:171806-171809） | → `Replicator.All`（ACS:174001-174014，另有 `IsMigrating` 守卫） |

服务端侧对 roster 的依赖：`EnterPlayer`/`LeavePlayer`（ACS:172169-172191）会
`MarkRosterDirty()` + `UpdateMemberCountMetadata(RoomMemberCountForMetadata())`。

### 2.4 观战者生命周期（全部是原版方法，我们只是调用者）

```text
EnterSpectator(Player spectator)                                   // private，ACS:170631-170653
  MakeSpectatorGhost()                 // IsAlive=false / State=Hide / IsGhost=true / 速度 840（ACS:175590-175600）
  AlivePlayers.Remove(spectator); DeadPlayers.Insert(0, spectator)
  MarkRosterDirty()
  黑方通知（S_NOTIFY_BLACK）
  SendSpectatorBootstrap(spectator)    // private，ACS:170655-...
      AreaManager.CreateCurrentMapPacket()（S_CURRENT_MAP）
      尸体元数据
      if (State == Survive || Detective)：S_TIME + MissionManager.SendMissionStateTo
                                          + 任务设备 S_MODIFY_DEVICE + GetArea(Pos).SendAreaInfo
                                          // ⚠️ 这一整段被 State 守着（ACS:170680-170694）
      if (State == Detective || Trial)：S_ADD_MY_CLUES / SendForensics / S_TAPE / 审判引导 / 照片 / 画板
  EnterGhostVisibility(spectator)      // public，ACS:169854-169894
```

`EnterGhostVisibility(dead)` 的四段（**"谁能看见谁"的唯一权威**）：

1. 给**其他所有人**发 `S_DESPAWN{dead}`（活人和幽灵都发）；
2. 双向清 `SharedPlayers`；
3. 给 `dead` 发**其他每个玩家**的 `S_SPAWN`（⇒ 幽灵能看到所有活人）；
4. 给**每个其他 `DeadPlayer`** 发 `S_SPAWN{dead}`（⇒ 其他幽灵能看到这个新幽灵）。

### 2.5 大厅复位

`StartLobby()`（ACS:170202-170318）：
`Players.Where(IsSpectator) → IsSpectator = false` + `MarkRosterDirty()`（ACS:170251-170255）、
`AlivePlayers/DeadPlayers.CorpseMetas` 清空、逐人 `InitLobby()`（ACS:170281；里面置 `IsAlive=true`，ACS:175741）、
逐人 `Move(LobbyPos, force:true)`（ACS:170286）。
⇒ **回大厅的复位是游戏自己的事，功能侧不需要写收尾。**

### 2.6 位置与区域（"人在地图上方 / 地板不显示"的根源）

| 方法 | 关键点 |
| --- | --- |
| `Player.Move(pos, force)`（ACS:175883-175921） | 写 `PublicInfo.Pos`/`EffectivePosition`；**`if (IsAlive)` 才 `ChangeArea(pos)`**；`force` 时广播 `S_RESPAWN`（ACS:175899-175900）并 `MoveLock=true`（100ms 后自解） |
| `Player.ChangeArea(pos, force)`（ACS:175871-175881） | **无 `IsAlive` 判断** → `CurrentArea.EnterPlayer` → `SendAreaInfo` |
| `Player.GameStart(pos)`（ACS:175773-175792） | 活人开局状态复位（含 `SkillComponent.ResetRoundState()`）→ `Move(pos, force:true)` |
| `Player.Clear()`（ACS:175856-175869） | 清 `CurrentArea` + `SharedPlayers`（`GameStart` 开头对所有人调，ACS:170086-170089） |
| `Area.SearchAndUpdatePlayer`（ACS:173427-173440） | `State == Hide` 直接跳过；否则逐人 `AddPlayer`（`AddPlayer` 里 `!IsAlive` 也返回 false，ACS:175822-175839） |

**客户端**只认一个门：`MapManager.ChangeArea(S_AREA_PUBLIC)`（ACS:29575-29603）

```text
flag = !Managers.Game.IsAlive
if (!flag || CurrentArea == null) { ... }   // 否则**整包丢弃**
```

⇒ 两条路必须分清（**这是本功能最容易写错的一处**）：

| 场景 | 客户端此刻 | 正确做法 |
| --- | --- | --- |
| **中途加入的观战者**（客户端刚进 GameScene，`CurrentArea == null`） | 已 `Dead()`（`IsAlive=false`） | 走 `Player.ChangeArea(pos, force:true)`（原版 `SendSpectatorBootstrap` 里 `GetArea(Pos).SendAreaInfo` 就是这条路；审判/结算阶段它被 State 守着不发，所以要自己补一次） |
| **已在房间的玩家转观战**（房主、满房超员；客户端 `CurrentArea` = 大厅房间） | 还活着（`IsAlive=true`） | **先 `Move(spawn, force:true)` 再 `EnterSpectator` 最后 `S_DEAD`**：`Move` 才写坐标并广播 `S_RESPAWN`，且此刻仍"存活"⇒ 走原版"存活玩家换区"下发游戏区 `S_AREA_PUBLIC`

`MapManager.ChangeRoom(data)`（ACS:29672-29710）对同一房间是幂等的（三段判断全跳过），
所以"区域包发两遍"无副作用。

## 3. 客户端机制地图（`GameManagerEX` / `UI_*` / `PlayerManager` / `MapManager`）

### 3.1 `Managers.Game.IsSpectator` 的写入口**只有三处**

| 写入点 | 位置 |
| --- | --- |
| `Clear()` → false | ACS:28904 |
| `StartLobby()` → false | ACS:29073 |
| `Handle_S_ENTER_GAME` → `pkt.IsSpectator` | ACS:42053 |

⇒ **进房之后想让客户端知道自己成了观战者，唯一通路是 roster**（`ApplyRoster` 里上游那个 Postfix 读"自己那条 entry"）。
丢掉它会导致一串看起来互不相关的毛病：

- 会议阶段旁观按钮不出现（`UI_TrialEvent.Init` 的 `GetObject(50).SetActive(IsSpectator)`，ACS:69823）；
- 观战面板不出现（`UI_GameScene.ShowUI` 的 `default:` 分支 `GetObject(40).SetActive(IsSpectator)`，ACS:75680）；
- `S_DEAD` 之后被当成"死亡"而不是"观战"（`Dead()` 里 `!IsSpectator` 才弹死亡提示、语音才走 Observe，ACS:28974/28979）；
- 幽灵不能自由移动（上游 `PostfixDead` 判的就是 `IsSpectator`）。

### 3.2 客户端 UI 的两个 ShowUI 出口

- `GameManagerEX.State` setter（ACS:28708-28724）→ `EndState` + `StartState`；
  `StartState`（ACS:29008-29033）= `BroadcastSceneEvent(HideAll)` + `BroadcastSceneEvent(ShowUI, (int)state)`。
- `UI_GameScene.ShowUI`（ACS:75611-75697）的分支（`GameObjects` 枚举 ACS:73886-73994）：
  `Trial`(75624, 关 40) / `Lobby`(75630, 关 40/42) / `Detective`(75649) / `Survive`(75658) /
  `TotalResult`(75672) / `default`(75676-75692：开 `Observe`(2) + `GetObject(40).SetActive(IsSpectator)` + `TimePanel`(6)) /
  `PickCharacter`(75693, 什么都不做)。
  - **`default` 分支就是"观战者那套 HUD"**：Observe + 观战面板（含退出房间按钮）+ 计时面板。
  - 选人界面由 `GameManagerEX.StartPick()`（ACS:29114-29117，`ShowSystemUI<UI_PickPopup>()`）单独弹。

### 3.3 `Dead()` 之后 HUD 为什么会没（已修，勿回退）

`Dead()`（ACS:28956-28980）：`IsAlive=false`、`CanControl=false`、`HideAll`（28972）、`CloseAllInGameUI`（28973）、
**`!IsSpectator` 才 `ShowDeadMessage()`**（28974-28977）。

- 原版**中途加入的观战者**不会踩坑：`Handle_S_ENTER_GAME` 里先 `Dead()`（ACS:42056）**之后**才赋
  `State = pkt.GameState`（ACS:42062）⇒ `State` setter → `StartState` → `StartSurvive` 的 else 分支
  （ACS:29167-29174：`HideAll` + `ShowUI(0)`）把 HUD 补回来，且 `ShowUI(0)` 正是观战者 HUD。
- **已在房间转观战**则是 `State` 先到、`S_DEAD` 后到 ⇒ `Dead()` 的 `HideAll` 成为最后一次场景事件，
  倒计时/观战面板全部留在隐藏态。
- 修法：在上游已有的 `PostfixDead`（`SpectatorJoin/Feature.cs`，本来就是"观战者死后保持自由移动"）
  里补一次等价的 `HideAll` + `ShowUI(0)`。房主观战与满房超员转观战**共用**这个补丁点。

### 3.4 `PlayerManager`：`_cache` 与 `Players` 是两件事

| 集合 | 语义 | 谁维护 |
| --- | --- | --- |
| `_cache` | **"房间里有哪些人"**（含未激活的） | `ApplyRoster`（ACS:31226-31299）—— 建条目时**跳过自己**（ACS:31239），`SetSpectator` 只对 `_cache` 里的条目调（ACS:31281，**所以自己那条不走这里**） |
| `Players` | "此刻屏幕上激活了谁" | `Spawn`/`Despawn`（ACS:31301-31343） |

- 差集处理（ACS:31284-31298）：`_cache` 里有、本次 roster 里没有 → `Despawn(S_LEAVE_GAME)` ⇒
  **`_cache.Remove` + 销毁 GameObject**（保护自己不删，ACS:31287）。
- `Despawn(int)`（ACS:31312-31325）**不动 `_cache`**；只有 `Despawn(S_LEAVE_GAME)`（ACS:31327-31343）才删。
- `Spawn(PublicPlayerInfo)`（ACS:31301-31310）**要求 `_cache` 里已有条目**（`Log.Assert(_cache.ContainsKey(...))`），
  否则什么都不做 ⇒ **不在 roster 里的人，即使发 `S_SPAWN` 也不会出现**。
- 选人格子与大厅人数标签都取自 `_cache`：`GetAllPlayers()`（ACS:31049-31052）、
  `GetPlayerCacheCount()`（ACS:31111-31130，随后 `UI_GameScene.UpadteRoomCount` 显示 `x/8`，ACS:74631-74638）。

### 3.5 幽灵可见性：可见即可见的唯一路径

- **活人看不见幽灵**、**幽灵看得见所有人**，全靠 §2.4 的 `EnterGhostVisibility` 四段包，
  以及 `Player.AddPlayer/RemovePlayer`（ACS:175822-175854，`AddPlayer` 要求**被介绍的人是活人**）。
- 死亡转幽灵时会再调一次 `EnterGhostVisibility(this)`（`Player` 内，ACS:176116），
  所以**中途死掉的玩家会通过那段"给 dead 发其他人的 S_SPAWN"看到房主** ——
  前提是房主在他的 `_cache` 里（见 §5.2 的坑）。

## 5. 硬约束与坑（违反任何一条都会得到难查的怪现象）

### 5.1 roster 必须**按收件人**分包

`BroadcastRoster()` 是**一个包发所有人**。若在 `BuildRosterPacket` 上删房主：

- ✅ 别人那边他整条消失（选人格子、人数标签一起走，因为都读 `_cache`）；
- ❌ **房主本人也收不到自己那条 entry** ⇒ §3.1 的观战标记断了。

正确做法：`BroadcastRoster` 的 Prefix 整替，给房主本人发**完整版**、给其他人发**摘掉他的版本**。
（`Replicator.All` 同源语义 + `IsMigrating` 守卫要自己复现。）

### 5.2 隐藏 = 从 `_cache` 摘掉 ⇒ 连幽灵也看不见他

只要在 roster 里摘掉他，别人的 `_cache` 就没有他 ⇒ `Spawn(PublicPlayerInfo)` 变成空操作（§3.4）⇒
**活人、幽灵都看不到房主**，且事后补 `S_SPAWN` 无效（要"建条目 + 激活"两步）。
⇒ 若希望"局内让其他幽灵看到房主"，隐藏只能覆盖**选人（与按配置的大厅）**，
进入局内必须恢复名单，并在恢复后补一次 `EnterGhostVisibility(host)`（把实体发给 `DeadPlayers`）。
*（本项为待实施修复，见 §7。原版"中途加入观战者"天然没这问题：`HandleEnterPlayer` 同帧先发
`S_ADD_PLAYER`（建条目，ACS:170607）再 `EnterSimulator`→`EnterGhostVisibility`。）*

### 5.3 区域包必须在 `S_DEAD` **之前**发出（否则地板不显示）

见 §2.6。`S_DEAD` 之后客户端 `IsAlive=false` 且 `CurrentArea != null` ⇒ `S_AREA_PUBLIC` 整包丢弃。

### 5.4 不要用 `Player.GameStart(pos)` 给观战者落位

它会跑 `SkillComponent.ResetRoundState()` 等"活人开局"复位（ACS:175784-175785），
而观战者没选过角色（`CharacterId = 0`，`SkillComponent.Data` 可能为空）。用 `Move(spawn, force:true)`。

### 5.5 Harmony 语义（决定"能不能叠补丁"）

- **所有 Prefix 都会执行**；任一返回 false ⇒ 跳过**原方法体**；
  `__result` 以**最后写入者**为准；Postfix **照常执行**（即使原方法体被跳过）。
- ⇒ 与上游改同一个方法时：**要么复用上游那个整替 Prefix 的判定点，要么显式写 `[HarmonyPriority]`**
  （AGENTS.md §9 红线；数值方向：`First = 800`、`Last = 0`，**值大者先跑**）。

### 5.6 段开关是"挂载后自判"，不是"不挂载"

DT_Tools 的日志里 `补丁已挂载（Host），Enabled=False` 说明**关掉的段补丁照样挂上**，
靠补丁体内第一行 `Engine.Enabled<T>()` 自判（AGENTS.md 红线 2）。
⇒ 上游 `SpectatorJoin` **段关着也可能在工作**（`ShouldHandleSpectators` = 它自己开着 **或** 有请求方）。
排查"明明是关的怎么还在动"时先看这一条。

### 5.7 配置字段是热的，但"推给别人的镜像值"不是

`ConfigBinder` 会给每个 `[Config]` 字段订阅 `SettingChanged` 并实时回写（`Core/Config/ConfigBinder.cs:42-45`），
所以功能内读裸字段永远是最新值。但如果这个值要被**推给另一个功能**（如 `HostSpectateMinParticipants`），
推送动作本身只在生命周期事件里发生 ⇒ **必须自己订阅一次**，否则改了配置不生效。

### 5.8 人数口径的三个不同数

| 数 | 来源 | 用途 |
| --- | --- | --- |
| Steam metadata `members` | `RoomMemberCountForMetadata()`（ACS:172193-172197）→ `UpdateMemberCountMetadata`（ACS:160443-160453） | 房间列表 `{Cur}/{Max}`、满员判定 |
| 房内标签 `x/8` | 客户端 `_cache` 计数（ACS:74631-74638，只在 Lobby 刷） | 纯显示 |
| `RoundStartPlayerCount` | `GameStart`（ACS:170084）/ 上游整替按 `!IsSpectator` | 黑方击杀上限 |

- 「0/8」**做不到**：房列表在 `members <= 0` 时回退读 Steam 真实成员数（ACS:160320-160323）。
- `Define.LOBBY_MIN_PLAYER` = **5**（playtest 包 0，ACS:93760-93770），可被 `[LobbyMinPlayers]` 改。
- 房主观战下"最小参与者人数"走 `[HostSpectate] MinParticipants`，**房主与观战者不计入**；
  判定点唯一在上游那个整替 `HandleStart` 的 Prefix（原版方法体被它整个替换，所以"手点"与"自动"都过这里）。
